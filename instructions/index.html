Project Details

Description

  • This project is a full-stack health data dashboard application designed to process and display patient health data. The backend processes clinical data from CSV files, applies risk assessment rules, classifies blood pressure stages, and computes statistical summaries. The frontend provides an interactive interface for viewing patient data, filtering by various criteria, and displaying aggregated statistics.
  • The application demonstrates a complete data pipeline: extracting raw patient data, transforming it through business logic, computing statistics, and presenting it through a simple (wireframed) web interface.
  • You will work with both the Python/FastAPI backend and the React/TypeScript frontend, implementing missing functionality across the full stack.

Core Features

  • Data Processing Pipeline The backend extracts patient data from CSV, enriches it with risk assessments and blood pressure classifications, and computes statistical summaries grouped by age bands.
  • Patient Filtering The frontend allows users to filter patients by risk level, blood pressure stage, and age band through interactive filter controls.
  • Statistics Dashboard The application displays aggregated statistics (mean, median, standard deviation) for key health metrics, organized by age bands in an easy-to-read card format.
  • Patient Table A comprehensive table displays patient information with expandable rows showing detailed risk assessment reasons and clinical data.
  • API Integration The frontend communicates with the backend API to fetch patient data and statistics, with proper error handling and loading states.

Your Role

  • As part of the assignment, you will be working on filling in certain "blanks" in the provided codebase.
  • All the tasks have been described step-by-step below. Simply follow these steps to complete the assessment.

Overall App Flow

  1. Backend Startup When the FastAPI server starts, it extracts patient data from CSV, processes it through transformation pipelines (risk assessment, BP classification), and computes statistics. The processed data is stored in memory.
  2. Frontend Initialization The React application loads and fetches patient data and statistics from the backend API endpoints.
  3. Data Display The frontend displays statistics cards showing aggregated health metrics and a patient table with all patient information.
  4. User Interaction Users can apply filters (risk level, BP stage, age band) to narrow down the patient list. The frontend sends filter parameters to the backend API.
  5. Filtered Results The backend processes filter requests and returns the filtered patient list. The frontend updates the table to show only matching patients.
  6. Detail View Users can expand table rows to view detailed risk assessment reasons and additional patient information.

Tech Stack

  • Python & FastAPI The backend is built with Python and FastAPI, handling data extraction, transformation, and API endpoints. You'll work with Pydantic models and enums.
  • React & TypeScript The frontend uses React with TypeScript for type safety. You'll work with React hooks (useState, useEffect, useCallback), Context API, and component composition.
  • Axios The frontend uses Axios for API communication, including interceptors for error handling and request configuration.
  • Pydantic The backend uses Pydantic for data validation and model definitions when processing patient data.
  • Version Control Git and GitHub are used to host this project's repository and for submitting your work.
  • Since this assessment will primarily use Git & GitHub, you will need a GitHub account and some experience working with the Git CLI.

Task 2 - Question 1: Patient Transformer Implementation

30 marks Spend 45-50 minutes

This is a full feature implementation task. You will implement the complete PatientTransformer class from scratch.

  1. Open the file backend/lib/transform.py. This file currently contains TODO comments indicating where you need to implement the PatientTransformer class.

  2. Understanding the Task

    The PatientTransformer class processes raw patient data through a transformation pipeline. It enriches patient records with:

    • Derived clinical metrics (pulse pressure, mean arterial pressure)
    • Blood pressure stage classification (AHA guidelines)
    • Risk assessment based on patient conditions
    • Final enriched patient objects with risk levels

    Review the following files to understand the data structures and how the class is used:

    • backend/custom_types/models.py - See the Patient and EnrichedPatient models
    • backend/custom_types/enums.py - See the BPStage and RiskLevel enums
    • backend/lib/load.py - See how PatientTransformer.enrich_patient() is called

  3. Implementation Requirements

    You must implement the following class methods:

    1. derive_metrics(patient: Patient, ctx: Dict[str, Any]) -> Dict[str, Any]
      • Calculate pulse pressure = systolic BP - diastolic BP
      • Calculate mean arterial pressure = (2 × diastolic BP + systolic BP) / 3
      • Store both values in the context dictionary and return it
    2. classify_bp(patient: Patient, ctx: Dict[str, Any]) -> Dict[str, Any]
      • Classify blood pressure according to AHA BP stage classification (see specifications below)
      • Set ctx["bp_stage"] to the appropriate BPStage enum value
      • Return the updated context
    3. apply_risk_rules(patient: Patient, ctx: Dict[str, Any]) -> Dict[str, Any]
      • Apply risk assessment rules based on patient conditions (see specifications below)
      • Update ctx["flags"] (list), ctx["score"] (int), and ctx["reasons"] (list) based on the rules
      • Return the updated context
    4. prepare_enriched_patient(patient: Patient, ctx: Dict[str, Any]) -> EnrichedPatient
      • Determine risk level based on score:
        • Score < 20 → RiskLevel.LOW
        • 20 ≤ Score < 40 → RiskLevel.MEDIUM
        • Score ≥ 40 → RiskLevel.HIGH
      • Convert patient data: smoker and diabetes must be converted to strings ("0" or "1") for Pydantic validation
      • Create and return an EnrichedPatient object with all enriched fields
      • Round mean_arterial_pressure to 2 decimal places
    5. enrich_patient(patient: Patient) -> EnrichedPatient
      • Main orchestration method that coordinates the transformation pipeline
      • Initialize context dictionary with: {"reasons": [], "flags": [], "score": 0}
      • Call methods in order: derive_metrics → classify_bp → apply_risk_rules → prepare_enriched_patient
      • Return the final EnrichedPatient object

  4. Specifications

    Blood Pressure Classification (AHA Guidelines)

    Classify blood pressure based on systolic and diastolic values using the following thresholds (check in order, use first match):

    • Hypertensive Crisis: Systolic ≥ 180 OR Diastolic ≥ 120 → BPStage.HYPERTENSIVE_CRISIS
    • Stage 2: Systolic ≥ 140 OR Diastolic ≥ 90 → BPStage.STAGE_2
    • Stage 1: Systolic ≥ 130 OR Diastolic ≥ 80 → BPStage.STAGE_1
    • Elevated: Systolic ≥ 120 (and doesn't meet above criteria) → BPStage.ELEVATED
    • Normal: All other cases → BPStage.NORMAL

    Risk Assessment Rules

    Apply the following rules to calculate risk score and collect flags/reasons:

    • Hypoxia: If oxygen_saturation < 92
      • Add "hypoxia" to ctx["flags"]
      • Add 30 to ctx["score"]
      • Add "SpO2 < 92% - hypoxia risk (+30)" to ctx["reasons"]
    • Hypertension: If blood_pressure_systolic ≥ 140 OR blood_pressure_diastolic ≥ 90
      • Add "hypertension" to ctx["flags"]
      • Add 15 to ctx["score"]
      • Add "BP in hypertension range (+15)" to ctx["reasons"]
    • Diabetes: If patient.diabetes == True
      • Add 10 to ctx["score"]
      • Add "Diabetes present (+10)" to ctx["reasons"]
    • Smoker: If patient.smoker == True
      • Add 5 to ctx["score"]
      • Add "Smoker (+5)" to ctx["reasons"]

    Formulas

    • Pulse Pressure: pulse_pressure = blood_pressure_systolic - blood_pressure_diastolic
    • Mean Arterial Pressure: mean_arterial_pressure = (2 × blood_pressure_diastolic + blood_pressure_systolic) / 3

  5. Key Requirements

    • All methods should be @classmethod decorators
    • Use the context dictionary pattern (ctx) to pass data between transformation stages
    • Return appropriate types: Dict[str, Any] for context methods, EnrichedPatient for final output
    • Handle all edge cases appropriately (e.g., ensure lists are initialized before appending)
    • Follow the exact specifications provided above for rules, thresholds, and formulas

  6. Testing Your Implementation

    • The server should start successfully and load patient data on startup

Task 3 - Question 2: Statistics Computation

20 marks Spend 30-35 minutes

This is a focused task with multiple parts. You will implement statistical computation functionality for the StatisticsComputer class.

  1. Open the file backend/lib/stats.py. This file contains TODO comments indicating where you need to implement three methods: get_age_band, compute_stats, and compute_statistics.

  2. Understanding the Task

    The StatisticsComputer class provides functionality for computing statistics on patient data. It includes:

    • Age band mapping (categorizing patients by age groups)
    • Basic statistics calculation (mean, median, population standard deviation)
    • Dataset-level statistics grouped by age bands for multiple health metrics

    Review the following files to understand the data structures:

    • backend/custom_types/models.py - See the Stats, AgeBandStats, and DatasetStatistics models
    • backend/custom_types/enums.py - See the AgeBand enum values
    • backend/lib/load.py - See how StatisticsComputer.compute_statistics() is used

  3. Part (a): Implement get_age_band method

    Map a patient's age to the appropriate age band according to the following ranges:

    • 0-17 → AgeBand.ZERO_TO_SEVENTEEN
    • 18-39 → AgeBand.EIGHTEEN_TO_THIRTY_NINE
    • 40-64 → AgeBand.FORTY_TO_SIXTY_FOUR
    • 65+ → AgeBand.SIXTY_FIVE_PLUS

    Requirements: Return the appropriate AgeBand enum value. Handle edge cases appropriately (e.g., boundary values).

    Implement this method where you see the TODO comment for Q2(a) in stats.py

  4. Part (b): Implement compute_stats method

    Calculate basic statistics from a list of numeric values. You need to compute:

    • Mean: The average of all values (sum divided by count)
    • Median: The middle value when values are sorted (if even number of values, average the two middle values)
    • Population Standard Deviation: Square root of the population variance. Use the formula: √(Σ(x - mean)² / n) where n is the total count (not n-1)

    Requirements:

    • Construct and return a Stats Pydantic model with the calculated values
    • Handle edge cases: if the input list is empty, raise a ValueError with an appropriate message
    • Important: Use population standard deviation (divide by n, not n-1)

    Implement this method where you see the TODO comment for Q2(b) in stats.py

  5. Part (c): Implement compute_statistics method

    Compute statistics for the entire dataset, grouped by age bands. This method should process patients and calculate statistics for three health metrics: blood_pressure_systolic, heart_rate, and glucose_fasting.

    Algorithm Overview: Follow a three-pass approach:

    1. Pass 1 - Bucket and Collect: Organize patients by age band and collect values for each metric into separate lists
    2. Pass 2 - Compute Statistics: For each age band and each metric, compute statistics using compute_stats. If a metric has no values for an age band, set it to None
    3. Pass 3 - Cleanup: If all three metrics for an age band are None, set the entire age band entry to None in the final result

    Requirements:

    • Initialize buckets for all four age bands with empty lists for each metric
    • Use get_age_band to determine each patient's age band
    • Extract and convert values to float for: blood_pressure_systolic, heart_rate, and glucose_fasting
    • Use compute_stats to calculate statistics for each metric in each age band
    • Handle empty lists by setting the corresponding statistic to None
    • Construct AgeBandStats objects for each age band with the computed statistics
    • In the final pass, set age band to None if all three statistics are None
    • Return a DatasetStatistics model with:
      • total_patients: Total number of patients in the input list
      • age_bands: Dictionary mapping age band strings to AgeBandStats objects (or None)

    Implement this method where you see the TODO comment for Q2(c) in stats.py

  6. Key Requirements

    • All methods should be @classmethod decorators
    • Use population standard deviation (divide by n, not n-1) in compute_stats
    • Statistics should be computed for exactly three metrics: blood_pressure_systolic, heart_rate, glucose_fasting
    • Follow the three-pass algorithm pattern: bucket → compute → cleanup
    • Handle edge cases appropriately (empty lists, missing values, etc.)
    • Ensure proper type conversions (e.g., convert patient field values to float)

  7. Testing Your Implementation
